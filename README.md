## Уведомление о форке и совместимость с оригиналом

> [!IMPORTANT]
> Данный репозиторий представляет собой специализированный форк проекта [toxicity188/BetterHud](https://github.com/toxicity188/BetterHud) (лицензия MIT, Copyright © 2024–2025 toxicity188).
>
> - **Заменяющий плагин:** Форк полностью заменяет оригинальный плагин BetterHud на сервере. **Не запускайте оба JAR-файла одновременно.**
> - **100% совместимость с серверным режимом:** При `animation-mode: server` или при обслуживании игроков Bedrock Edition поведение плагина полностью идентично оригинальному BetterHud.
> - **Внесённые изменения:** В форке реализован рендеринг анимаций на GPU клиента через Core Shaders, режим exact для передачи 24-битного RGB цвета текста без потерь, схема dual для сохранения цветной тени текста, независимые диспетчерские ID и команды переключения режимов.

## Возможности, добавленные в форке

1. **Плавные анимации на клиенте (144+ FPS):**
   - Расчёт перемещения, прозрачности и заполнения полос прогресса вынесен в вершинные Core Shaders (`text.vsh`, `text.fsh`).
   - Анимация интерполируется на каждом кадре дисплея по внутриигровому `GameTime`, обходя ограничение 20 тиков в секунду.
2. **Точный 24-битный цвет текста попапов (`text-client-mode: exact`):**
   - Честный полный спектр RGB (16 777 216 цветов) без дискретных палитр и без искажения оттенков.
   - Полная поддержка hex-цветов MiniMessage, градиентов и плейсхолдеров.
3. **Цветная тень текста в клиентском режиме (`text-shadow-mode: dual`):**
   - Схема с двумя копиями текста (слой тени + слой текста) передаёт и цвет текста, и цвет тени.
   - Не зависит от Z-буфера и теста глубины OpenGL; правильный порядок наложения гарантируется последовательностью вершин в 2D-буфере.
4. **Разделение диспетчерских ID:**
   - Независимый пул диспетчерских ID для клиентских и серверных лейаутов (ёмкость 1024, занято меньше 6%).
   - Отдельные файлы шрифтов для клиентских вариантов (`_client.json`), позволяющие переключать режим индивидуально для каждого игрока.
5. **Переключение режима на лету:**
   - Команда `/hud animation-mode <player|self> <client|server|auto>` позволяет переключать режим анимаций без перезагрузки сервера (реализовано, не проверено в клиенте с несколькими игроками).
   - Игроки Bedrock Edition (через GeyserMC / Floodgate) автоматически получают серверный рендеринг без ручной настройки.
6. **Инструменты диагностики:**
   - `/hud debug-anim`: Дерево активных элементов интерфейса с отображением текущего режима (`[CLIENT]` или `[SERVER]`) и делителей M.
   - `/hud debug-popup <popup> [hold|stop]`: Заморозка попапа на экране для визуальной проверки и выравнивания.

## Статус тестирования

> [!NOTE]
> **Фактический статус проверок:**
> - **Проверено в игре:** Протестировано и подтверждено в реальном клиенте **только на версии Minecraft 26.1.2** (сервер Purpur 26.1.2, ванильный клиент и сборка Fabulously Optimized, проверено при **GUI scale 2 и 3**).
> - **Fabulously Optimized (Sodium, Iris):** Сборка Fabulously Optimized (Sodium, Iris) с обычными ресурспаками работает корректно. Поведение со сторонними шейдерпаками Iris/OptiFine, переопределяющими пайплайн рендеринга текста, не проверялось; при возникновении артефактов переключите игрока в серверный режим командой `/hud animation-mode self server`.
> - **Bedrock Edition (Geyser / Floodgate):** Логика автоматического выбора серверного варианта для игроков Bedrock реализована, но с реальным Bedrock-клиентом не тестировалась.
> - **Остальные оверлеи Minecraft:** Оверлеи `betterhud_1_21_4`, `betterhud_1_21_6`, `betterhud_26_2`, `betterhud_26_3` проверены синтаксически через автоматические компиляционные тесты (`ShaderLintTest` / `glslangValidator`); в реальном клиенте этих версий они не запускались.

## Настройка (`shader.yml`)

Параметры клиентских анимаций настраиваются в файле `plugins/BetterHud/shader.yml`:

```yaml
# Режим выполнения анимаций:
# - client: вычисления в клиентских вершинных шейдерах (где поддерживается).
# - server: классический серверный рендеринг (100% ванильная совместимость).
# - hybrid: клиентский режим для Java-игроков и серверный режим для Bedrock-игроков (Floodgate/Geyser). Реализовано, в реальном клиенте с Bedrock не проверялось.
animation-mode: client

# Режим отображения текста в клиентских попапах:
# - exact: честный 24-битный RGB без палитры и квантования цвета.
# - off: серверный рендеринг текста (20 тиков/сек).
text-client-mode: exact

# Режим тени текста в клиентских попапах:
# - dual: вывод двух копий (слой тени + слой текста) с точными цветами текста и тени.
# - off: вывод текста в одну копию без тени (экономит вершины буфера).
text-shadow-mode: dual

# Поведение при невозможности отобразить тень (например, длительность превышает окно M=120):
# - exact: плавная клиентская анимация с точным цветом текста, но без тени.
# - server: серверный рендеринг с ванильной тенью (20 тиков/сек).
text-shadow-fallback: exact

# Безопасное резервное копирование и обновление папки plugins/BetterHud/shaders при старте/reload.
# При включении старые шейдеры переименовываются в shaders.bak-<время> (сохраняется до 3 копий).
# По умолчанию: false
delete-shaders-on-start: false

# Максимальное упреждение тиков (lookahead) для компенсации сетевого пинга игрока.
animation-lookahead-max: 5

# Замедление анимаций для отладки (1.0 = нормальная скорость).
animation-debug-slowmo: 1.0

# Включение отладочного зонда и тестовой матрицы цветов (только для разработки).
animation-debug-probe: false
```

> [!TIP]
> **Обновление шейдеров (`delete-shaders-on-start`):**
> Если установить параметр в `true`, плагин при старте или перезагрузке автоматически создаст резервную копию `shaders.bak-<время>` (хранится не более 3 архивов) и извлечёт чистые шаблоны шейдеров. По умолчанию значение `false`, чтобы не затронуть пользовательские модификации шейдеров.

## Известные ограничения (Known Limitations)

1. **Ограничение длительности для тени (`text-shadow-mode: dual`):**
   - В схеме dual используются диапазоны альфы от 1 до M (текст) и от M+1 до 2M (тень), что накладывает ограничение: 2M не больше 240 (меньше 255).
   - Максимальная длительность клиентского попапа с тенью составляет около 115 тиков (M не больше 120).
   - Попапы большей длительности автоматически следуют политике `text-shadow-fallback` (`exact` без тени либо `server` с частотой 20 Hz).
2. **Форматирование и стили текста:**
   - Стили `bold` и `italic` полностью поддерживаются (скос italic компенсируется в GLSL-шейдере).
   - Стили `underlined`, `strikethrough` и `obfuscated` не поддерживаются клиентским пайплайном: парсер BetterHud (`Component.split`) сохраняет только `bold` и `italic`. Подчёркивание, зачёркивание и обфускация отсекаются при формировании строк (на экране нет артефактов, текст отображается без этих линий).
3. **Канал прозрачности тени:**
   - Ванильный генератор компонентов Minecraft отсекает альфа-канал цвета текста (альфа всегда 255). В теневом кваде передаётся только RGB; кастомная прозрачность тени игнорируется.
4. **Количество вершин в режиме dual:**
   - Режим dual генерирует две копии строки для каждого текста с тенью, что удваивает число вершин буфера для таких строк.
5. **Головы игроков (Player Heads):**
   - Головы игроков рендерятся на сервере (`[SERVER]`) из-за динамической загрузки скинов по сети Mojang.
6. **Bedrock Edition (Geyser / Floodgate):**
   - Клиенты Bedrock не поддерживают Java Edition Core Shaders и автоматически получают серверный рендеринг.

## Команды администратора

- `/hud animation-mode <player|self> <client|server|auto>`: Переключение режима анимаций для конкретного игрока или себя без перезагрузки сервера (реализовано, не проверено в клиенте с несколькими игроками).
  - `auto`: Клиентский режим для Java Edition, серверный режим для Bedrock Edition.
  - `server`: Принудительный классический серверный рендеринг.
  - `client`: Принудительный клиентский режим на GPU.
- `/hud debug-anim`: Просмотр дерева зарегистрированных элементов HUD, их режима (`[CLIENT]` или `[SERVER]`) и делителей M.
- `/hud debug-popup <popup> [hold|stop]`: Вызов и удержание попапа на экране для визуального анализа.

## Сборка из исходного кода

### Требования
- JDK 25 или новее (например, Eclipse Adoptium Temurin 25 или OpenJDK 26)
- Git

### Команды сборки
```bash
# Клонирование репозитория форка
git clone https://github.com/KeylHenrih/BetterHUD-fork.git
cd BetterHUD-fork

# Сборка всех модулей и запуск тестов
./gradlew build --no-daemon

# Сборка готового плагина для Bukkit / Paper / Purpur
./gradlew :bootstrap:bukkit:shadowJar --no-daemon

# Собранный файл: build/libs/BetterHud-bukkit-2.2.0-fork.1.jar
```
