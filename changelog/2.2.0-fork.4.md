# BetterHud 2.2.0-fork.4

Релиз стабилизации и ужесточения клиентского шейдерного пайплайна BetterHud.

### Changes since fork.3:
1. **Приоритет слотов шейдеров и откат на серверный вариант (B):**
   - Клиентским шейдерам отдан безусловный приоритет при заполнении слотов 1..1023.
   - Лейауты, превысившие лимит 1023 уникальных слотов, теперь автоматически и побайтово откатываются на свой серверный вариант (`serverFallback`).
   - Исключено появление белых букв без заливки и отправка протокольных квадов ($A \in [1..240]$) в пустой `case 0:`.
2. **Многопоточный LRU-кэш без внешних зависимостей (E):**
   - Внешняя библиотека `net.jodah:expiringmap` полностью удалена из проекта и shadowJar.
   - Кэши текста переведены на стандартную библиотеку Java `Collections.synchronizedMap(LinkedHashMap(accessOrder = true, removeEldestEntry))` с жестким лимитом в 2048 записей.
   - Подтверждена потокобезопасность на серверах Folia (16 параллельных потоков) и ускорение в 12.7x.
3. **Безопасная обработка динамических плейсхолдеров со стилями (`<u>`, `<st>`, `<obf>`) (G):**
   - Если динамический плейсхолдер (урон, оповещение, баланс) содержит неподдерживаемые шейдерами декорации `<u>`, `<st>` или `<obf>`, они автоматически отсекаются функцией `stripUnsupportedClientDecorations()` перед генерацией клиентских квадов.
   - Текст, градиенты и цветная тень сохраняются в полном объёме; исключено схлопывание текста за экран в координаты `(-10000, -10000)`.
   - Добавлен rate-limited вывод предупреждения в консоль (не чаще одного раза в 10 секунд на лейаут).
4. **Устранение сетевого оверхеда при удержании попапов (`hold`) (D):**
   - Во время `hold`, а также в промежутке между окончанием анимации (`animDuration`) и безопасным окном ($M - L - 1$), эффективный базовый тик фиксируется (`effectiveBaseTick = baseTick`).
   - Adventure-компонент остаётся 100% побайтово неизменным от кадра к кадру, снижая сетевой трафик до строгого 0 обновлений после завершения анимации.
5. **Аппаратная инвариантность серверных квадов (I):**
   - Проверена идентичность поведения серверного текста между старыми и новыми шейдерами на 10,000 квадов через OpenGL Transform Feedback на физическом GPU: расхождение координат 0.000000 px, расхождение цвета 0.000000.
   - Все 4 шаблона `text.vsh` приведены к строгому стандарту GLSL (явные `0.0`, `1.0`, блоки `default: { break; }`).
6. **Компенсация наклона курсива (`italic`), отладочный попап `debug_italic_popup` и анализатор скриншотов:**
   - В шейдере текста `text.vsh` реализована аналитическая компенсация скоса вершин курсивных глифов в закодированных шрифтах: $\Delta X = 0.25 \times (pos.y - 10.0 - isBottom \times 8.0) + 1.75$ (расчётное значение, подтверждённое экранным замером в клиенте 26.1.2 с точностью 0.000 GUI-px).
   - Добавлен автоматический попап `debug_italic_popup` для проверки компенсации наклона курсива на высотах $Y \in \{-100, 0, 50, 200\}$ без необходимости ручной правки пользовательских конфигов (активируется при `animation-debug-probe: true`).
   - Добавлен скрипт `tools/screenshot-analyzer/analyze_italic_pairs.py` для автоматического измерения выравнивания глифов на скриншотах с субпиксельной точностью (допуск 0.25 GUI-пикселя).
7. **Расширенный инструмент анализа паритета конфигураций (`tools/config-parity-tool`):**
   - Выводит время жизни, длительность анимации, lookahead, выбранный делитель $M$ и безопасный запас тиков (`margin`).
   - Проверяет паритет на 3 различных наборах данных плейсхолдеров (короткий текст, кириллица, MiniMessage с градиентами).

### Known Limitations:
1. **Аппаратная поддержка:**
   Аппаратное тестирование шейдеров выполнено на драйвере Mesa Intel OpenGL 4.6 (Core Profile) и валидаторе `glslangValidator`. Поведение на видеокартах NVIDIA GeForce, AMD Radeon и Apple Silicon (macOS/Metal) синтаксически выверено, но не проверялось на реальных устройствах.
2. **Декорации текста ванильного шрифта:**
   Стили `<u>` (подчёркивание), `<st>` (зачёркивание) и `<obf>` (обфускация) не поддерживаются ванильным шейдером текста Minecraft в режиме трансформации квадов. Статические лейауты с этими тегами остаются на серверном рендере; в динамических плейсхолдерах эти три стиля отсекаются с предупреждением в логе.
3. **Игроки Bedrock Edition:**
   Для игроков, подключенных через Geyser/Floodgate, шейдерный режим принудительно отключается с автоматическим откатом на серверный рендер, так как клиент Bedrock не поддерживает Java Edition core shaders.
4. **Слоты анимаций:**
   Максимальное число одновременно зарегистрированных клиентских шейдеров ограничено 1023 уникальными слотами. При превышении этого количества избыточные лейауты безопасно переключаются на серверный вариант отображения.
